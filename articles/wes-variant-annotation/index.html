WES系列⑨｜变异注释：给基因变异一个“身份”

“找到变异只是第一步，知道它是谁、能干什么，才是解开基因奥秘的关键。”

1. 为什么要做变异注释？

在变异检测得到 VCF 文件后，每个位点只是一个坐标加上一些碱基信息。它到底落在哪个基因？是不是会改变蛋白质结构？在普通人群中常见吗？有没有已知的致病记录？这些问题都需要变异注释来回答。

变异注释的目的，就是为每个变异添加背景信息，让它从“坐标”变成一个有生物学意义和临床参考价值的“故事”。在科研中，它能帮助研究者锁定潜在功能重要的位点；在临床中，它则是精准医疗报告的核心内容之一。

2. 变异注释的主要内容

变异注释通常包含以下几类信息：

  • 基因信息：变异所在的基因名称、转录本 ID、位于外显子/内含子/剪接区的具体位置

  • 功能影响：是否导致氨基酸改变（错义、无义、移码）、产生提前终止密码子、影响剪接等

  • 人群频率：在 gnomAD、1000 Genomes、ExAC 等数据库中的等位基因频率

  • 致病性信息：ClinVar、HGMD 等数据库中已有的临床意义分类及相关证据

  • 进化保守性：变异位点在不同物种中是否保守（PhyloP、PhastCons、GERP）

  • 预测打分：SIFT、PolyPhen-2、CADD、REVEL 等工具对功能影响的预测结果

  • 药物与治疗信息：OncoKB、CIViC 等药物反应及治疗建议数据库的匹配信息

3. 主流的注释工具

3.1 ANNOVAR

  • 支持多种数据库注释

  • 灵活性高，可定制化注释内容

  • 有强大的过滤功能，能在注释时直接设定条件筛选

3.2 VEP（Variant Effect Predictor）

  • 由 Ensembl 提供，数据库更新及时

  • 支持 REST API 调用，适合云端和大规模批量分析

  • 输出结果详细，包括多转录本的注释信息

3.3 SnpEff / SnpSift

  • 注释速度快

  • 对多种物种的基因组支持较好

  • 配合 SnpSift 可进行灵活的变异过滤

4. 数据库资源

常用的变异注释数据库包括：

  • dbSNP：已知的单核苷酸多态性集合，适合做背景参考

  • gnomAD：大规模人群变异频率数据，帮助区分常见多态与罕见突变

  • ClinVar：临床变异意义及其证据等级

  • HGMD：已知致病突变集合（部分功能需订阅）

  • COSMIC：肿瘤体细胞变异数据库

  • OMIM：遗传病与相关基因的权威资源

5. Germline 与 Somatic 注释的差异

  • Germline 注释 更关注遗传性疾病数据库（如 ClinVar、OMIM）、人群频率数据库（如 gnomAD）以及家系共分离分析结果。

  • Somatic 注释 则更多依赖肿瘤特异数据库（如 COSMIC、OncoKB）、药物靶向信息库（如 CIViC、MyCancerGenome）以及分子分型信息。

在实际工作中，注释流程会根据检测目的调整：遗传病筛查侧重罕见致病变异，肿瘤检测则会优先报告可药靶向的驱动变异。

6. 注释结果的解读

注释的结果往往是一个包含几十到上百列信息的表格，每行一个变异。例如：

  • 基因名：BRCA1

  • 变异类型：错义（p.Glu23Lys）

  • ClinVar 致病性：致病

  • gnomAD 频率：0.0001

  • SIFT 预测：有害

  • PolyPhen-2 预测：可能有害

  • OncoKB 证据等级：Level 1（FDA 批准的靶向药）

解读过程中需要结合多方面证据：

  • 多数据库一致性

  • 是否有功能验证文献

  • 在患者临床表型中是否合理

7. 注意事项

  • 数据库版本要与参考基因组版本匹配（hg19/hg38）

  • 不同数据库之间信息可能冲突，需要综合判断

  • 预测工具的结果仅为参考，不能单独作为结论

  • 对于意义不明确的变异（VUS），应结合家系验证、功能实验或长期随访进一步分析

  • 肿瘤样本要区分驱动变异与乘客变异（passenger mutation）

小结

变异注释让冰冷的坐标有了“姓名”和“故事”，是连接测序数据与临床决策的桥梁。无论是科研还是临床，只有经过充分且严谨的注释，变异过滤、致病性评估和精准医疗才有坚实的基础。
