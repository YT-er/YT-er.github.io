hg19：一张老地图，为什么还在临床里常用？

在参考基因组的世界里，hg19 是一个很特别的名字。它不算新。它也不算最完整。如果只从技术版本的角度看，hg19 早就不是最新的人类参考基因组。后面有 hg38，有 T2T，还有正在快速发展的 pangenome。

可是，只要走进真实的临床检测场景，尤其是遗传病、肿瘤 Panel、全外显子组测序、历史样本复盘和数据库比对，我们仍然经常会遇到 hg19。很多实验室的流程还在用它。很多老数据库的坐标还在用它。很多报告中的经典位点，最早也是在 hg19 坐标体系下被大家熟悉的。

这就像一张用了很多年的城市地图。它不是最新的地图，有些地方画得不够精细，有些新区没有标全，可是很多路名、门牌号、老档案、办事流程，仍然和它绑定在一起。

hg19 到底是什么？

hg19 是 UCSC Genome Browser 对人类参考基因组 GRCh37 的命名。在不同系统里，我们经常会看到几个相近的名字：hg19、GRCh37、b37。它们经常被混在一起说，但严格来说并不完全等同。

hg19 通常指 UCSC 体系下的 GRCh37 版本，染色体命名习惯是 chr1、chr2、chrX、chrM。

GRCh37 是 Genome Reference Consortium 发布的人类参考基因组版本，染色体命名更常见的是 1、2、X、MT。

b37 则是 Broad 等流程中常用的一套 GRCh37 相关参考，常见于 GATK 早期最佳实践和很多历史分析流程。

对很多刚接触生信的人来说，这些名字看起来只是格式差异。实际工作中，它们会带来不少麻烦。比如同样是1号染色体，在 hg19 里常写作 chr1，在 GRCh37 或 b37 里可能写作1。线粒体在不同版本里可能叫 chrM，也可能叫 MT。有些参考文件是否包含 decoy 序列、alt contig、unplaced contig，也可能不同。所以，当我们说“这个流程用 hg19”时，最好不要只停留在一个名字上，还要具体确认参考 FASTA 文件、染色体命名、索引文件、注释资源和 bed 区域是否完全匹配。

很多看似奇怪的报错，比如 contig 不一致、chr 前缀不匹配、tabix 查不到区域、VEP 注释失败，背后都可能是这些细节没有对齐。

为什么 hg19 曾经如此重要？

要理解 hg19 的地位，需要把时间往回拨。在很长一段时间里，hg19 是人类基因组分析事实上的主力参考版本。早期的大量二代测序流程，都是围绕 hg19 或 GRCh37 建立的。无论是 WES、WGS、肿瘤 Panel、GWAS，还是很多公共数据库和商业检测平台，都曾经长期使用这一套坐标体系。

这带来了一个非常强大的生态效应。工具支持它，数据库收录它，文献引用它，实验室验证它，临床报告熟悉它，用户也习惯它，于是 hg19 不再只是一套参考序列，而是逐渐变成了一个巨大的历史坐标系统。

很多经典变异位点、疾病相关区域、商业 Panel 的 bed 文件、实验室内部阳性样本库，都是在 hg19 体系下积累起来的。

这就是 hg19 最强的地方。它的优势不是最新，而是大家都用过。在临床检测里，这一点非常重要。新不一定马上胜过旧。对于一个已经验证过、积累过、运行稳定的临床流程来说，参考基因组版本一旦改变，整个体系都要重新评估。

变异坐标会变，注释结果可能会变，过滤阈值可能要重新设定，历史阳性样本需要重新回测，报告系统和数据库也要跟着迁移。这不是改一个参数就能完成的事情。

hg19 的优势：生态成熟，历史数据多

hg19 最大的优势，可以概括成四个字：生态成熟。

第一，它有大量历史数据。

很多实验室从早期就开始基于 hg19 建库。每一次检测，每一个阳性样本，每一次人工判读，每一个报告结论，都会逐渐沉淀成经验。这些经验很珍贵。对于临床实验室来说，历史数据不是负担，也是资产。尤其在遗传病和肿瘤检测中，内部数据库往往能帮助快速判断一个变异是否曾经出现过、是否与某种表型相关、是否有类似家系或类似病例。

如果这些数据都基于 hg19，那么继续使用 hg19 就可以减少大量转换成本。

第二，很多数据库长期支持 hg19。

ClinVar、dbSNP、gnomAD、COSMIC、1000 Genomes、ExAC 以及各种疾病数据库，都曾经提供过 hg19 或 GRCh37 坐标版本。虽然很多新资源正在向 hg38 迁移，但 hg19 版本的资源仍然非常常见。

第三，工具链非常成熟。

从 BWA、GATK、samtools、bcftools，到 VEP、ANNOVAR、SnpEff，再到各种 CNV、SV、Panel 分析流程，hg19 相关的参数、资源和经验都非常丰富。

第四，临床人员熟悉。

很多医生、遗传咨询师、生信分析人员、报告审核人员，对 hg19 坐标下的经典区域和经典位点已经非常熟悉。熟悉本身就是一种稳定性。这也是为什么 hg19 到今天依然有现实价值。

hg19 的问题：老地图终究有局限

不过，hg19 的问题也很明确。

第一，它不够完整。

早期参考基因组中有很多 gap。尤其是高度重复区域、着丝粒、端粒、大片段重复区域，受限于当时的测序和组装技术，很多地方没有被准确表示。这些区域在常规 WES 中影响可能没有那么明显，但在 WGS、SV、重复区域分析、复杂基因家族分析中，影响会更突出。

第二，它有一些参考序列错误或不理想区域。

任何参考基因组都不是绝对完美的。hg19 作为较早版本，里面有一些后来被修正的问题。对于某些位点、某些基因区域，使用更高质量的参考版本可能会获得更合理的比对和变异检测结果。

第三，它对复杂变异不友好。

hg19 是线性参考基因组。它用一条主参考路径表示人类基因组。对于 SNV 和小 Indel，这种方式通常足够实用。但对于大片段插入、缺失、倒位、重复、复杂重排，以及人群中高度多态的区域，一条线性参考很难充分表示所有真实差异。

第四，它可能带来 reference bias。

参考基因组并不是从所有人群平均构建出来的。传统参考序列更接近少数个体的基因组。如果某些人群中常见的序列没有被参考基因组很好表示，那么这些人的测序数据在比对和变异检测时就可能处于不利位置。这类偏倚在复杂区域和结构变异中尤其值得关注。所以，hg19 的确好用，但它不是没有代价。

它像一张老地图。熟悉、稳定、资料多，但有些地方画得粗，有些地方没有画，有些新道路根本不存在。

为什么不能简单地把 hg19 换成 hg38？

很多人会问：既然 hg38 更好，为什么不直接全部换成 hg38？这个问题在技术上看起来简单，在临床实践中却很复杂。因为参考基因组是整个流程的地基。一旦地基改变，上面的很多东西都要跟着调整。

首先，坐标会改变。

同一个变异，在 hg19 和 hg38 中可能对应不同的染色体位置。对于 SNV 和小 Indel，可以通过 liftover 进行坐标转换，但转换并不是百分之百无损。有些区域能顺利转换，有些区域转换后位置不唯一，有些区域无法转换，有些复杂变异本身就很难用简单坐标转换描述。

其次，bed 区域要重新处理。

WES 和 Panel 流程通常依赖捕获区域 bed 文件。hg19 的 bed 不能直接拿到 hg38 上用。即使用 liftover 转换，也需要检查区域是否丢失、是否拆分、是否发生边界变化。

第三，注释数据库要匹配。

参考基因组版本变了，VEP cache、ANNOVAR 数据库、ClinVar 坐标、gnomAD 版本、基因注释 GTF/GFF、转录本资源，都要确认是否同步。

第四，质控阈值可能变化。

比对率、重复率、覆盖度、目标区域捕获效率、CNV log2 ratio、MAPD、fold80 等指标，可能因为参考版本或 bed 区域变化而出现差异。临床流程不能默认旧阈值继续适用。

第五，历史病例要重新比较。

如果实验室多年积累的数据都在 hg19，迁移到 hg38 后，需要考虑历史病例如何复用，内部数据库如何转换，旧报告如何追溯，新旧流程如何并行。

这就是为什么很多临床实验室即使知道 hg38 更先进，也不会轻易在短时间内全部迁移。换参考基因组，不是升级软件那么简单，更像是给整栋楼换地基。

hg19 适合哪些场景？

虽然 hg19 有局限，但它仍然适合一些场景。

第一，历史数据复盘。

如果过去的检测结果、报告坐标、内部数据库都基于 hg19，那么复盘时继续使用 hg19 可以减少转换误差。

第二，成熟临床流程。

一些已经经过充分验证的 WES、Panel、遗传病或肿瘤检测流程，如果短期内没有足够资源重新验证 hg38，继续使用 hg19 是现实选择。

第三，依赖旧数据库或旧软件的项目。

有些项目的核心资源只有 hg19 版本，或者 hg38 版本质量不稳定。此时使用 hg19 可能更稳妥。

第四，与历史文献和既往研究保持一致。

一些老文章、老队列、老 GWAS、老 Panel 数据使用 hg19。为了可比性，后续分析可能也会保留 hg19。

但是，如果是新建流程，尤其是 WGS、结构变异、非编码区、RNA 分析或长期维护的大型项目，就应该认真考虑使用 hg38 作为起点。

使用 hg19 时要注意什么？

如果一个流程继续使用 hg19，建议特别关注几个细节。

第一，明确写清楚参考版本。

报告、流程文档、数据库字段中，最好明确标注 hg19 或 GRCh37，并说明对应的参考 FASTA 来源。不要只写“人类参考基因组”。

第二，统一染色体命名。

chr1 和1的差异看似很小，却能导致很多工具报错。VCF、BED、FASTA、BAM、注释数据库之间必须统一。

第三，确认线粒体命名。

chrM、MT、M 的差异在实际流程中很常见。尤其是 mtDNA 分析或全基因组流程中，需要提前处理。

第四，注意 decoy 和 alt contig。

不同 hg19/GRCh37 参考构建可能包含不同的附加序列。是否加入 decoy，会影响某些重复区域和污染序列的比对表现。不同流程之间比较结果时，不能只看名字都叫 hg19，还要看具体 FASTA 是否一致。

第五，liftover 后必须检查。

从 hg19 转 hg38，或者从 hg38 转回 hg19，都不能只相信转换结果。关键位点、复杂区域、临床报告变异，需要人工或程序化复核。

第六，注释资源要成套匹配。

hg19 的 VCF 不应该直接用 hg38 的注释库。bed、FASTA、VEP cache、ClinVar、gnomAD、转录本资源，都需要在同一坐标体系下工作。

这些细节看起来琐碎，却是保证结果可靠的关键。

hg19 会被淘汰吗？

从长期趋势看，hg19 的使用比例会逐渐下降。新数据库、新工具、新研究会更多支持 hg38，复杂区域研究会更多关注 T2T 和 pangenome。对于新建的大型基因组项目，继续从 hg19 起步的理由会越来越少。

但在临床场景中，hg19 不会很快消失。因为临床检测重视连续性、可解释性和可追溯性。只要大量历史报告、历史数据库、验证体系、经典位点还在 hg19 坐标下，hg19 就会继续存在。

更可能出现的局面，是多版本长期共存。hg19 负责承接历史和成熟流程。hg38 成为新流程和主流线性参考的核心。T2T 用于补充复杂区域和完整基因组研究。pangenome 逐渐进入更前沿的群体和复杂变异分析。

所以，hg19 的角色会变化。它会从主流新项目的默认选择，逐渐变成历史数据和成熟临床生态的重要坐标。但它不会立刻退出。

小结

hg19 是一张老地图。它的优势在于生态成熟、历史数据丰富、工具支持广泛、临床体系熟悉。它的问题也很明显：不够完整，对复杂区域和结构变异不够友好，也可能带来参考偏倚。对于已经成熟的临床流程，继续使用 hg19 有现实理由。对于新建流程，尤其是 WGS、SV、RNA、非编码区和长期维护项目，hg38 通常更值得优先考虑。

真正重要的是，不要把 hg19 当成一个简单的文件名。使用 hg19，就要确认 FASTA、BED、BAM、VCF、注释数据库、转录本资源、坐标命名和报告系统都在同一个坐标体系里。

参考基因组是地图，也是坐标系统。地图可以老，但不能混。
