WES系列⑥｜WES原始数据（FASTQ）的质量控制

“原始数据就像刚出锅的米饭，看起来热气腾腾，但要想做出好吃的寿司，还得先检查它的质量。”

🎯 1. 为什么要做质量控制（QC）？

当我们从测序平台拿到原始的FASTQ文件时，并不能直接进入变异分析。原因很简单：测序过程中可能会引入各种“杂质”，比如：

  • 低质量碱基：在测序末端常见，影响比对准确性。

  • 接头序列污染：测序读长超过插入片段时，可能读入接头序列。

  • GC含量偏差：极端GC区域容易导致覆盖度不均。

  • 重复序列：可能是PCR扩增带来的冗余数据。

QC的目的，就是在进入分析前，先把这些潜在问题揪出来并处理。

📂 2. FASTQ文件结构回顾

每条测序读段（read）由四行组成：

  1. @开头的ID行：包含样本名、测序通道等信息

  2. 碱基序列：由A/T/C/G组成

  3. +分隔符：可附带ID

  4. 质量值行：对应每个碱基的Phred质量分数

Phred质量分数（Q值）与测序错误率的关系：

  • Q20：错误率约1%

  • Q30：错误率约0.1%

WES数据通常要求Q30比例≥80%。近年来，随着测序技术进步，部分平台和项目开始参考更高的质量标准，如Q40（错误率约0.01%）甚至Q50（错误率约0.001%），以追求更高的测序准确性和下游分析可靠性

🛠 3. 常用的质控指标

指标 说明 参考标准或注意事项
碱基质量分布 查看每个位点的质量值分布，末端低质常见 WES常要求Q30≥80%
序列长度分布 测序读段应有统一长度 异常分布可能提示文库或测序异常
GC含量分布 应接近人类基因组的GC比例（约38%~42%） 偏差过大需警惕文库偏倚或污染，同时要注意由于测序平台的GC偏好性，实际测序的平均GC含量可能接近50%
接头污染比例 测序时可能读入接头序列 接头残留会导致比对错误，应分析前去除
序列重复率 不同读段出现重复的比例 高重复率可能降低有效信息量，常因PCR过多或测序深度过高引起

这里的序列重复率属于FASTQ层面的统计，不能直接等同于BAM中的位置重复。两种口径的区别见NGS Duplicates的统计口径。

🔍 4. 质控与处理流程

目前很多分析流程会直接使用 fastp：它把“质控 + 清洗”做成了一站式工具，可替代 FastQC + Cutadapt 等组合，速度快、资源占用低，并自动生成 HTML 与 JSON 报告，包含质量分布、GC含量、接头检测等多种信息，方便快速浏览。 fastp的能力包括：自动识别并去除接头、按位质量剪切、滑窗修剪、长度/低复杂度过滤、polyG/polyX 处理、双端读段的重叠校正与去接头、去重复评估、UMI 解析与写入、并行多线程等。

常用命令示例（PE 数据）：

fastp \
  -i sample_R1.fastq.gz -I sample_R2.fastq.gz \
  -o sample_R1.clean.fastq.gz -O sample_R2.clean.fastq.gz \
  --detect_adapter_for_pe \
  --cut_front --cut_tail --cut_window_size 4 --cut_mean_quality 20 \
  --length_required 50 \
  --thread 8 \
  --html sample_fastp.html --json sample_fastp.json

参数：--detect_adapter_for_pe 自动识别双端接头；--cut_* 为滑窗质量修剪；--length_required 设最短保留长度；--html/--json 输出报告；--thread 指定线程数。

💡 5. QC结果解读技巧

  • 如果Q值整体偏低：检查文库构建质量或测序仪状态。

  • 如果GC分布异常：考虑是否有污染（如细菌DNA）。

  • 如果重复率高：可能测序深度过高或PCR扩增过多。

📌 小结

质量控制是WES分析的第一道“安检门”，能有效减少下游分析中的噪音，让我们更有信心地解释最终的结果。
