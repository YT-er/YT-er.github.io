WES Series 7 | From FASTQ Alignment to SAM/BAM

“Receiving a collection of ‘ATCG’ strings is like being handed a bag of puzzle pieces. The next step is to fit them back onto the complete blueprint of the human genome.”

1. Why Is Alignment Necessary?

FASTQ files produced by a sequencing platform contain millions to hundreds of millions of short sequences, or reads. These reads do not know where in the genome they originated. The purpose of alignment is to return these “lost little sentences” to their correct positions in the reference genome.

2. The Reference Genome

A reference genome is like a “standard map.” Human studies commonly use the following reference-genome versions:

  • GRCh37/hg19: an older version on which many clinical databases are based

  • GRCh38/hg38: the latest version, which corrects errors in the preceding version and adds previously missing regions

Reference-genome versions must be used consistently, or genomic coordinates will become misaligned.

3. Core Principles of Alignment

The central challenge for an alignment algorithm is to locate the most likely genomic origin of a read quickly and accurately within an enormous reference genome. Common methods include seed-and-extend strategies and efficient compressed indexes based on the Burrows–Wheeler transform (BWT) or FM-index, which enable rapid searches with limited memory.

Because the human genome is approximately 3 billion bp long while sequencing reads are typically only 100–150 bp, exhaustive direct matching is virtually impossible. Mainstream algorithms such as BWA-MEM and Bowtie2 use indexing to reduce the search space dramatically:

  • Index construction: divides the reference genome into searchable segments and constructs an index

  • Seed matching: first matches a short sequence (the seed), then extends the match in both directions

  • Scoring system: assigns scores based on matches, mismatches, deletions, and other features, then selects the highest-scoring location as the alignment result

4. Alignment Output Files: SAM and BAM

Alignment produces a SAM file (Sequence Alignment/Map):

  • A human-readable text format

  • Contains each read's location, mapping quality (MAPQ), CIGAR string (describing matches, deletions, and insertions), and other information

To save storage space and accelerate access, SAM files are generally compressed into BAM format (Binary Alignment/Map):

  • Advantages: smaller and faster to read

  • Disadvantage: requires a specialized tool such as samtools to inspect

A BAI index file is also used to access data from a specific region in a BAM file quickly.

5. The BAM File Format in Detail

A BAM file is a binary alignment-results file compressed from SAM format. It has two main components:

  • Header: describes the reference-genome version, alignment software, alignment time, and other metadata

  • Alignment section: each record contains the alignment information for one read, including the read name, reference-sequence name, alignment start position, MAPQ score, CIGAR string, paired-alignment information, nucleotide sequence, and quality scores.

BAM fields occur in the same order as SAM fields, but are stored in binary form. Common fields include:

  • QNAME: read name

  • FLAG: an integer encoding alignment status as multiple binary bits, each representing a distinct state. For example, 1 indicates that the read is paired; 2 that the read is mapped in a proper pair; 4 that the read is unmapped; 8 that its mate is unmapped; 16 that the read maps to the reverse strand; 32 that its mate maps to the reverse strand; 256 that the record is a secondary alignment; and 1024 that the read is a PCR or optical duplicate

  • RNAME: reference-sequence name

  • POS: alignment start position

  • MAPQ: mapping-quality score

  • CIGAR: string describing matches, deletions, insertions, and other alignment operations

  • RNEXT/PNEXT: information about the paired read

  • TLEN: template length

  • SEQ: nucleotide sequence of the read

  • QUAL: corresponding base-quality scores

⚠ Note: FLAG values combine multiple bits. A value of 99, for example, simultaneously represents the states 1 + 2 + 32 + 64.

FLAG 1024 indicates only that a read has been marked as a duplicate; it does not mean that the read has been removed from the BAM file. For the distinctions among marking, removal, and duplication-rate definitions, see NGS Duplicates: What Exactly Is Being Duplicated?

6. Common Alignment-Quality Metrics

Metric Meaning Reference standard
Mapping rate Percentage of reads successfully aligned to the reference genome Commonly > 98% for WES data
Unique mapping rate Percentage of reads aligned to only one location Higher is better
Mean sequencing depth Average number of times each position is sequenced Commonly > 100× for WES
Coverage Percentage of the exonic target region covered at least once Commonly > 95% for WES
Uniformity Consistency of sequencing depth across positions > 80%

7. The Role of BAM Files in Downstream Analysis

BAM files are the “foundation” of WES data analysis. All subsequent variant calling, CNV analysis, visual inspection, and other steps depend on high-quality BAM files. Alignment bias directly compromises the accuracy of downstream analyses.

Common uses:

  • Variant calling (SNV/InDel calling)

  • Structural-variant analysis (SV calling)

  • CNV analysis

  • Visual inspection in IGV (reviewing sequencing evidence at a variant site)

8. Important Considerations

  • Watch for PCR duplicates: too many duplicate reads reduce usable information; they can be marked with markdup

  • Watch for a low mapping rate: it may indicate sample contamination, mixed species, or failed library preparation

  • Keep reference-genome versions consistent: the reference genome used for analysis should match the versions used by downstream databases

  • Review aligner parameters: different parameter settings can substantially affect alignment results

Summary

Alignment is the “puzzle-assembly stage” of the WES workflow, and the BAM file is the analysis's “core raw material.” Only an accurate alignment provides a solid foundation for subsequent variant calling.
